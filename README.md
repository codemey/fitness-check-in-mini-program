# 个人训练打卡小程序

每天记录训练；训练部位可在设置中自定义，不操作的日期保持未记录。计划页按周一至周日制定每周循环安排，今日页可将当天计划填入表单，只有保存后才算实际训练。历史日历区分计划与打卡，月度和年度统计只计算实际训练。修改训练部位或计划不会改写过去的记录或计划。数据保存在微信云开发 CloudBase 的文档型数据库，不在手机上维护第二份记录。

## 结构

- `miniprogram/`：今日、历史、计划、设置页面及业务逻辑。
- `cloudfunctions/records/`：账号校验、记录、训练部位、计划及备份接口。
- `workout_records`：云数据库集合；计划和部位设置以独立文档保存，不混入训练记录查询。
- `tests/`：不连接真实云环境的本地测试。

## 准备

1. 从 `project.config.example.json` 创建本地 `project.config.json`，填入自己的小程序 AppID；从 `miniprogram/config.example.js` 创建本地 `miniprogram/config.js`，填入自己的文档型云开发环境 ID。这两个本地文件被 Git 忽略。不要把微信账号密码、AppSecret 或云密钥填入代码。
2. 安装并登录微信开发者工具，用对应小程序的管理员微信打开本目录。在云开发控制台核对环境 ID。若环境是从当前小程序的开发者工具创建，按[官方说明](https://docs.cloudbase.net/quick-start/create-env)会自动关联当前小程序。核对免费配额、到期时间和续期规则。
3. 在云开发控制台创建集合 `workout_records`，将客户端权限设为「所有用户不可读写」；云函数使用云端权限访问。如提示缺少索引，为集合建立 `(ownerId, month)` 和 `(ownerId, date)` 复合升序索引。
4. 部署 `records` 云函数并在云端安装依赖。首次部署可不设置 `OWNER_OPENID`，此时记录操作会被拒绝，仅「设置」页可读取当前微信账号的 OpenID。
5. 手机微信扫描预览码，打开「设置」查看自己的 OpenID。给云函数 `records` 设置环境变量 `OWNER_OPENID`，按控制台提示更新函数使配置生效。刷新「设置」页看到「已绑定当前微信账号」后再开始记录。**不要把 OpenID 写入代码或仓库。**

如果使用的是与小程序原生 `wx.cloud` 不兼容的 CloudBase 环境（例如选了 PostgreSQL 而不是文档型数据库），需要重新选择对应环境，不能直接套用这份数据库代码。

### 模拟器提示 INVALID_ENV / Environment not found

此错误发生在小程序连接云环境时，尚未进入 `records` 云函数或 `workout_records` 集合。先核对 `miniprogram/config.js` 的环境 ID 与控制台中的完整 ID 是否一致，再确认 `project.config.json` 的 AppID 是关联该环境的小程序 AppID，并检查环境是否已完成初始化。重新打开项目并编译后若仍报错，按[官方错误码说明](https://docs.cloudbase.net/error-code/INVALID_ENV)排查。若接下来提示云函数不存在，按第 4 步部署 `records`。

## 验证

- 本地运行 `npm run check`：检查 JS / JSON 和关键业务逻辑；本地测试使用内存云数据库替身，不会连接真实 CloudBase。
- 在手机上保存「胸 + 肩」，返回今日查看是否仍为多选；历史页检查当天，并查看月度、年度统计；删除后这天应显示为「未记录」。
- 用同一微信账号在另一部手机打开开发/体验版，确认历史记录同步；使用不同微信账号时云函数应拒绝访问。
- 「设置」页可将记录与计划一起复制为 JSON 文本做备份，也可粘贴或从剪贴板读取备份并导入。导入会覆盖同日期记录、保留其他日期；新版备份会替换当前计划版本，旧版仅含记录的备份不会改变计划。旧版备份中的「没练」条目会跳过。导出时间使用本地 `YYYY-MM-DD HH:mm:ss` 格式。
- 修改训练部位后，旧记录会保留原部位名称，在历史记录和月度统计中仍可查看；备份导入也接受这些名称。

云环境创建、AppID 绑定、`OWNER_OPENID` 设置及真机云同步须使用自己的微信账号和云环境执行。云开发免费体验的资源与有效期按控制台展示的规则管理。
